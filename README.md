# NovaRetail SQL Analysis

## Project Overview

NovaRetail is a fictional retail company operating several stores across France.

The objective of this project is to analyze retail sales data using PostgreSQL in order to evaluate commercial performance, customer behavior, product performance, and data quality.

This project was created as part of my SQL Data Analyst portfolio.

## Business Questions

The analysis aims to answer questions such as:

- What is the total revenue generated by completed orders?
- Which stores generate the most revenue?
- Which stores have the highest average order value?
- Which products generate the most revenue?
- Which products are sold in the highest quantities?
- Which customers generate the most revenue?
- Which customers can be considered strategic?
- How dependent are stores on their top customers?
- Which product categories dominate each store?
- How can store performance be evaluated using several KPIs?

## Dataset

The dataset is synthetic and was generated specifically for this portfolio project.

It contains:

- 250 customers
- 8 stores
- 40 products
- 800 orders
- 1,777 order items

Order statuses include:

- completed
- cancelled
- returned
- pending

Only completed orders are included in sales revenue analyses.

The dataset also contains a small number of missing values to allow realistic data-quality checks.

## Database Structure

The database contains five relational tables:

- `customers`
- `stores`
- `products`
- `orders`
- `order_items`

### Main relationships

- One customer can place multiple orders.
- One store can process multiple orders.
- One order can contain multiple order items.
- One product can appear in multiple order items.

## Revenue Calculation

Net revenue is calculated using:

`quantity × unit_price × (1 - discount_pct)`

When `discount_pct` is NULL, it is treated as 0 using `COALESCE()`.

## Analysis Workflow

The project follows a structured analytics workflow:

1. Create the PostgreSQL relational database.
2. Import the CSV datasets.
3. Validate table sizes and relationships.
4. Perform data-quality checks.
5. Analyze sales performance.
6. Analyze products and customers.
7. Build more advanced business KPIs.
8. Interpret the results from a business perspective.

## Key Initial Findings

Initial analysis showed that store performance should not be evaluated only through revenue.

Revenue, order volume, average order value, customer concentration, and product mix can lead to different rankings depending on the KPI used.

The analysis also highlights the importance of checking data granularity when joining `orders` and `order_items`, as one order can contain several product lines.
